# 幕织 Muweave

[简体中文](README.md) | [English](README.en.md)

**Weave your story. 织就你的故事。**

幕织是一个使用 Electron、React 和 TypeScript 构建的本地 AI 导演台。从剧本对话、人物与场景资产、分镜视频到整集成片，在同一个项目中完成创作。既可作为独立桌面软件运行，也可通过插件在 Codex 和 iPolloWork 中使用 Studio 页面。

项目、素材和任务记录保存在本机；AI 生成可分别连接 ChatGPT 或文字、图片、视频服务商的官方 API。当前运行环境以 **Windows x64** 为主。

## 快速启动

### 环境要求

- Windows x64、Node.js **22.13 或更新版本**、npm。
- 安装依赖、连接账号和调用生成服务时需要网络。
- Windows 开发启动会自动准备 FFmpeg 与 ffprobe，无需用户手动填写路径。

在项目根目录执行：

```sh
npm ci
npm run dev
```

首次启动可选择“探索示例项目”，包含原创「雨夜来信」剧本、人物与场景资产、分镜示例；示例不附带生成的视频或图片结果。

侧栏底部或“连接与设置”可切换中文 / English、浅色 / 深色。偏好保存在本机，切换语言不会翻译或改写已有剧本、项目名称和资产内容。

运行已构建的桌面版：

```sh
node scripts/prepare-ffmpeg.mjs
npm run build
npm start
```

Windows 安装版和免安装版的构建命令见[开发与验证](#开发与验证)。安装包目前未做代码签名；macOS 尚未进行实机验证。

## 连接生成服务

在“连接与设置”中配置。项目内容和生成服务凭据分别存储，插件复用同一套本地配置。

### 独立模型与 Key 配置

设置页分为**文字模型 / 图片模型 / 视频模型**。三个通道可以选择不同服务；即使都选择 OpenAI，也分别保存各通道的 Key，不自动复用。旧设置会保留原有 ChatGPT 与 RunningHub 连接。

| 通道 | 支持服务 | 接入方式 |
| --- | --- | --- |
| 文字：剧本、对话、资产提取、分镜 | ChatGPT、OpenAI、DeepSeek、通义千问、Claude、Gemini、Kimi、智谱 GLM、豆包、MiniMax、Grok、Mistral、腾讯混元、百度文心、阶跃星辰 | ChatGPT 账号或各服务的官方 API Key |
| 图片：资产参考图、镜头首尾帧 | ChatGPT、OpenAI GPT Image、通义万相、Gemini、Seedream、MiniMax Image-01、Grok Imagine、FLUX、GLM-Image / CogView | 独立的图片服务授权，结果自动入库 |
| 视频 | RunningHub、可灵、MiniMax 海螺、Seedance、Grok Imagine | 独立视频 Key；可灵支持新版 API Key 或旧版 Access Key + Secret Key |

1. 选择生成通道和服务商，选择或填写模型 ID，再填写该通道的 Key。
2. 通义、可灵、MiniMax、Kimi、GLM 支持中国大陆与海外接口，区域 Key 不可混用。豆包 / Seedream / Seedance 使用火山方舟中国区；Grok、Mistral、FLUX 使用官方国际接口。文字 / 图片模型 ID 可按同接口能力修改；视频、万相和 FLUX 图片从已适配模型中选择。
3. 保存后无需复制提示词或跳转网页。模型及区域在入队时记录，后续切换服务不会改变已排队任务的模型。使用同服务的新账号 Key 前应先处理旧账号的未完成任务。
4. “检查连接”使用不收费的模型或任务查询；万相、MiniMax、火山方舟、GLM、FLUX 只确认配置已保存，不冒充已验证生成权限，也不提交付费测试。

新增预设包括 Kimi K3 / K2.6、GLM 5.3 / 5.2 / 4.7 / 4.6V、Doubao Seed 2.1 / 2.0、MiniMax M3 / M2.7 / M2.5、Grok 4.7、Mistral Small / Large，Seedream 5.0 / 4.5 / 4.0、Image-01、Grok Imagine Image 2.0、FLUX.2 Pro / Max / Flex / Klein，以及 Seedance 2.5 / 2.0 / Fast 和 Grok Imagine Video 1.5。模型是否可用取决于官方账号、区域和开通权限；接口适配使用隔离测试验证，未宣称真实账号付费生成已验证。

进一步扩展了混元 TurboS / T1、文心 4.5 Turbo / Turbo VL、Step 3.7 Flash / 3.5 Flash，以及 GLM-Image / CogView-4。混元与文心使用中国区接口；StepFun 支持中国区与国际区，区域 Key 分开保存。混元、非视觉文心和 Step 3.5 不接受图片附件；Step 3.7 支持视觉输入。新增文字接入通过提示词请求 JSON，仍由共享数据契约验证结果，不冒充严格结构化输出。智谱图片从已适配预设选择，按模型设置尺寸，下载不附带 Key。混元、StepFun 的连接检查只确认配置保存，不提交付费测试。Veo、Runway 尚未适配，不能在当前设置中调用；Sora Videos API 已下线，不作为可用预设。

本轮官方参考：[混元](https://cloud.tencent.com/document/product/1729/111007)、[文心](https://cloud.baidu.com/doc/qianfan-api/s/3m7of64lb)、[StepFun](https://github.com/stepfun-ai/Step-3.7-Flash)、[智谱图片](https://docs.z.ai/api-reference/image/generate-image)、[Sora 下线公告](https://developers.openai.com/api/docs/deprecations)。

Seedance 与 Grok 视频接入支持 4–15 秒和首尾帧，按原有队列顺序生成；Seedance 需要同时提供首帧才能设置尾帧，Grok 允许单独尾帧。当前这两个接入不传递前镜头音轨或多资产参考图，原生声音不等于音色继承保证。FLUX 保存任务 ID 和服务返回的集群查询地址，重启后只继续查询原任务；查询地址经官方域名和路径校验后才附带 Key，下载图片不附带 Key。

新增接入依据：[Kimi 模型与 API](https://platform.kimi.com/docs/models)、[GLM Chat API](https://docs.z.ai/api-reference/llm/chat-completion)、[火山方舟视频 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)、[Seedream](https://docs.volcengine.com/docs/ark/seedream-4-0-5-0?lang=zh)、[MiniMax 文字](https://platform.minimax.io/docs/api-reference/text-openai-api)、[MiniMax 图片](https://platform.minimax.io/docs/api-reference/image-generation-t2i)、[Grok 图片](https://docs.x.ai/developers/model-capabilities/images/generation)、[Grok 首尾帧](https://docs.x.ai/developers/model-capabilities/video/reference-to-video)、[FLUX](https://docs.bfl.ai/quick_start/generating_images)、[Mistral](https://docs.mistral.ai/api)。

API 费用由对应服务商账户承担；ChatGPT 订阅不包含 OpenAI API 额度。文字服务分析文件时，现有解析器先提取文本；图片附件需要有视觉能力的文字模型。本次 DeepSeek 接入只处理文字，图片附件会明确提示更换服务。

视频仍按镜头顺序串行生成，同场景使用上一镜实际尾帧。RunningHub 保留多参考图、前镜音视频参考和 RH币计费检查。可灵适配首尾帧与 2.6 原生声音；本次接口不继承前镜音轨或多参考图。海螺适配首帧与 6 / 10 秒无声视频，配音需另行导入；没有首帧时仅支持横屏。需要人物、环境和音色多参考连续时使用 RunningHub。所有结果仍需人工检查。

万相图片保存远端任务 ID；重新查询或重启恢复时只查询原任务。付费提交结果未知时不自动重试。新视频服务的任务 ID 也保留在任务中心；不支持远端取消的接口不会显示已远端取消。

导演台的批量视频弹窗支持全选与清空选择，每批最多 100 个镜头。镜头检查器支持将关联资产、场景、景别、运镜、光线和时长批量应用到同场景、本集或手动选择的其他镜头；资产默认追加绑定，也可明确选择替换。一次批量修改保存为一个项目历史版本，已有视频的输入发生变化时会标记需要更新，镜头动作、对白和素材版本保留。

任务中心统一显示 AI 与视频任务：正在执行的任务置顶，其余按安排时间倒序排列。完成、失败或已终止的任务可删除本地记录，生成素材仍保留；尚被同批镜头依赖的失败记录需先处理同批任务。“全部终止任务”会取消排队任务并停止本地生成和下载，之后提交的新任务正常执行；任务中心不再提供全局暂停功能。提交中的视频先等待返回 ID，再尝试远端取消；结果未知时保留待核实记录，不重新提交。服务商不支持取消或取消失败时仅终止本地处理，可凭保留 ID 人工核实或继续查询，已发生费用以服务商为准。

接入依据：[OpenAI Images API](https://developers.openai.com/api/docs/guides/image-generation)、[DeepSeek API](https://api-docs.deepseek.com/)、[通义 OpenAI 兼容接口](https://help.aliyun.com/zh/model-studio/compatibility-of-openai-with-dashscope)、[万相生图](https://help.aliyun.com/en/model-studio/text-to-image-v2-api-reference)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)、[Gemini Interactions](https://ai.google.dev/api/interactions-api)、[可灵官方 API](https://kling.ai/document-api/api/video/2-6/image-to-video/legacy)、[MiniMax 海螺](https://platform.minimax.io/docs/api-reference/video-generation-i2v)。

### ChatGPT：文字与图片

连接一次 ChatGPT 账号，通过随软件提供的 Codex 运行时生成剧本、分镜和图片。参考图生成完成后会直接保存到对应资产或镜头，并选中为当前版本，无需复制提示词、跳转其他页面或手动导入结果。

这使用的是 **Codex 的 ChatGPT 账号授权**，不代表通用第三方 OAuth。幕织不读取或外传浏览器 Cookie、会话 Token 或账号密码；旧版浏览器辅助仅作兼容保留，不参与当前直接生图流程。可用能力与额度取决于账号和运行时，授权失效或额度不足时会显示实际错误。

AI 对话中的“创作思路”是面向用户的创作摘要，不是模型的隐藏推理过程。

### RunningHub：视频

1. 填写 RunningHub **消费级会员 API Key**。
2. 选择 **Standard** 或 **Plus**。
3. 在导演台选择镜头，确认生成后加入队列。

内置中国站的[“导演台”工作流](https://www.runninghub.cn/workflow/2105215916815511553?source=workspace)，ID 为 `2105215916815511553`。用户无需配置工作流 ID 或节点映射。Standard 对应接口参数 `instanceType: "default"`，Plus 对应 `"plus"`；模式在加入队列时记录，修改设置不会改变已排队任务。

当前采用 RH 币生成路径，一次运行一个视频任务。软件在入队及提交前检查账号，要求 `apiType: "NORMAL"` 且有 RH 币余额；工作流节点也必须通过白名单校验。会使用钱包计费的 Key、未核准节点或不匹配的工作流会阻止提交。实际扣费与余额以 RunningHub 账单为准。

付费任务创建结果不确定时，**不会自动重新提交**。请先在 RunningHub 核实，再在任务中心绑定已存在的 Task ID、恢复查询。已提交任务的取消和费用以平台状态为准。

### FFmpeg：预览与导出

Windows 开发启动及打包脚本自动准备 `vendor/ffmpeg/`，优先复用符合要求的本机 Gyan 构建，否则下载并校验固定版本。Windows 发行包附带 FFmpeg、ffprobe 和许可文件，用户无需安装或配置路径。来源和许可记录随包保存在 `resources/ffmpeg/NOTICE.txt`。

## 制作流程

### 从故事到分镜

1. **创建项目与分集**：选择 `16:9`、`9:16` 或 `1:1`，输入故事或在 AI 编剧中对话。
2. **应用剧本**：查看候选内容，点击“应用到剧本”。每次 AI 返回剧本后，可以选择两个建议润色方向之一，或输入自定义方向再润色；也可以选择“不润色”保留此版。润色基于点击时选中的候选剧本，返回完整的新候选版本，由用户手动应用；选择“不润色”不会发起生成。切换分集、项目或工作页面时会先保存编辑，也可手动保存。
3. **准备资产**：固定人物外观、服装、场景布局和道具描述，上传 PNG / JPEG / WebP 或直接生成参考图。
4. **AI 拆解分镜**：生成可编辑的镜头；核对动作、说话人、对白、时长和关联资产。结构化导入会复用同名同类型资产，新镜头追加到当前集。
5. **生成视频**：按镜头顺序加入队列，审看每个结果，必要时修改后人工重试。
6. **预览与导出**：整集镜头都有视频后，在成片页连续播放，再导出影片或分镜表。

剧本对话可选择任意扩展名的附件，每轮最多 **10 个**，每个最多 **50 MB**。目前支持提取文本、DOCX 和 PDF 文字，PNG / JPEG / WebP 作为图片输入；其他文件尝试按文本读取。文字提取最多 30,000 字符，PDF 最多读取前 30 页。扫描件、受保护文件或无法解析的二进制格式会说明原因，不保证所有文件类型都能分析。

### 人物与场景连续性

内置多参考图路径使用 MiniMax H3 Ref2VA。软件按镜头关联的资产选择人物、场景和道具参考图，最多 **9 张**；参考图版本在入队时固定。同场景后续镜头等待前一镜头完成，再参考它的末帧和视频；前镜头含音轨时，视频与音轨一起作为参考。前镜头失败时，后续连续镜头暂停；没有任何参考图的新场景使用保留的 FL2VA 路径。

**局部重生成**会自动接回两侧保留的视频：同场景前镜视频的实际尾帧作为开场参考，后镜保留视频的实际首帧作为收尾目标，优先于手动首尾帧。保留视频的版本在入队时固定。连续重生成多个镜头时，中间镜头依次使用新生成的前镜尾帧，只有这一段的最后一镜使用后方保留视频的首帧；不引用本批即将替换的旧视频。没有相邻视频的一侧不添加自动首尾帧，也不越过缺失镜头去找远处视频。人物、环境及道具资产仍作为身份参考，与首尾帧约束分开。

生成窗口逐镜显示首尾帧来源。提示词加入前后镜头动作及构图关系，要求仅执行当前镜头的动作和对白，不重演前镜、不提前演后镜、不凭空跳跃或转场。RunningHub Ref2VA 将两端帧作为标明用途的参考图；可灵使用首尾帧接口。当前海螺接口不支持尾帧控制，需要接回后镜时会在提交前提示改用 RunningHub 或可灵，避免忽略收尾约束后收费。

提示词会标明参考图编号及用途，并传入角色设定、说话人和对白。时长预览与入队使用同一套当前视频适配规则：RunningHub、Seedance 和 Grok 为 **4–15 秒**，可灵为 **5 / 10 秒**，海螺为 **6 / 10 秒**。短镜头与对白时长不足的镜头会在确认生成时补足到可用时长，增加时长可能提高费用。对白按正常语速估算，只有超过所选适配器上限时才需要拆镜；手动设置的镜头时长超限也会阻止提交。生成窗口列出全部超限镜头，允许一键取消勾选后继续生成其他镜头。整批镜头先校验，通过后才保存时长调整并创建视频任务。

参考图和前镜头能改善连续性，生成模型仍可能改变人物、环境或对白，也不会严格锁定首帧。关键角色和地点应使用稳定的设定及选定参考图，并逐镜审看。

### 3D 预演与参考视频

在「导演台 → 3D 预演」或镜头检查器「打开 3D 预演」进入。首次按关联人物、场景建立片场；多个镜头可选用同一片场，也可复制片场后单独调整。片场对象和镜头轨道通过共享 Zod 契约保存到现有 SQLite 项目文档，随项目 ZIP 导入导出；旧项目无需迁移操作。

- 添加人物、桌椅、墙体、门框和基础形体；可关联现有人物/道具资产，调整位置、朝向、尺寸和颜色，或隐藏、锁定对象。GLB 模型须内嵌缓冲区和贴图，最大 50 MB；不加载模型中的外部地址，不支持 Draco、Meshopt 或 KTX2 压缩。导入模型作为静态物件，基础动作应用于内置人偶。
- W/E/R 切换移动、旋转和缩放。选择人物或摄影机后点击「绘制轨迹」，在地面逐点布置路径并应用；人物会增加行走动作，摄影机保持设定高度。支持站立、行走、奔跑、坐下和挥手片段，以及推近、平移、环绕和跟随运镜。运镜预设替换当前机位轨道，支持撤销。
- 时间轴支持播放、拖动、添加/删除关键帧；拖动菱形或使用左右方向键移动关键帧。动作只控制白模表演，不修改当前镜头对白。编辑自动保存；共享片场修改会影响引用它的预演，已导出版本提示重新导出。
- 「导出构图图」保存当前摄影机画面；「导出白模视频」按 24 FPS 逐帧渲染并调用 FFmpeg 编码无声 MP4，支持取消。两者保存为独立镜头素材，不替换正式视频或首尾帧。输出采用约 480p 的横/竖画幅或 640×640 方形，渲染临时帧总量最多 512 MB。预演依赖 GPU/WebGL，三维代码在打开时加载。
- 勾选「视频生成使用预演参考」后，仅允许当前已适配的 RunningHub H3 Ref2VA 路径。入队固定预演视频版本；预演、片场或镜头时长改变后需重新导出。生成时长需要补足时先调整镜头时长，再导出预演，避免静默拉伸。
- 工作流分别传入前镜音视频与当前无声白模视频：前者负责连续性和合适的声音参考，后者负责当前走位、动作和运镜；人物、场景与道具外观仍由正式参考资产和设定提供。同场景前镜实际尾帧、局部重生成的保留后镜实际首帧继续优先用于衔接。云端工作流不是 Ref2VA 或固定素材缺失时，在付费提交前阻止。
- H3 参考视频总时长最多 15 秒、每段至少 2 秒。同时引用前镜时，白模最长 13 秒；前镜按剩余额度截取真实尾部并保留可用音轨，边界图仍来自原视频实际尾帧。前镜不足 2 秒或无法满足额度时阻止提交，不静默丢弃参考。规格依据：[MiniMax H3 官方输入限制](https://huggingface.co/MiniMaxAI/MiniMax-H3#model-variants)。

本地预演、截图和导出不调用 AI 生成服务；启用后提交视频生成才上传对应参考素材。模型仍可能偏离白模路径、构图或人物外观，不承诺逐帧复刻或零变形。自动化验证使用替身和本地渲染，不代表真实账号生成已验证。图片自动重建三维场景、复杂骨骼编辑与动作重定向不在当前版本范围内。

实现依赖 Three.js（MIT）及其类型声明；现有 React Flow 负责二维分镜，不能替代三维渲染、摄影机与变换控件。Three.js 与模型加载器独立按需加载，不影响普通列表和画布的初次加载路径。

代码职责分别由 `shared/previs.ts` 的契约和时间计算、`renderer/Previs.tsx` 的编辑状态与表单、`renderer/previs-stage.ts` 的 WebGL 与资源释放、`main/previs.ts` 的渲染会话与编码持有。编辑器复用现有 UI、项目存储和桥接层；没有第二套场景数据库、全局状态库或视频任务队列。

### 视频生成规范

RunningHub 生成窗口和视频模型设置可选择清晰度：标准档横屏 **864×480**、竖屏 **480×864**、方形 **640×640**；高清档分别为 **1344×768**、**768×1344**、**1024×1024**。这是生成节点的输出尺寸，高清会增加计算量，可能延长生成时间及提高费用，不保证消除模型造成的模糊。清晰度和画幅在入队时固定，后续修改设置不影响已安排的任务；旧任务按标准档继续处理。导出到 1080p 会缩放已有素材，不能恢复源视频中缺失的细节。

以下是软件批量视频生成的执行规则和成片验收要求，适用于桌面版、插件和 Studio；相关画面、对白与声音约束自动加入提交给模型的提示词。

1. **按顺序串行生成**：以项目分集顺序和导演台镜头顺序为准，与勾选顺序或传入 ID 的顺序无关。每次仅提交一个视频任务，前一任务生成、下载并保存完成后再提交下一任务；同批较早镜头仍在等待或暂停时，后面的镜头不能越过它。
2. **上一镜尾帧衔接**：同场景的下一片段提取上一片段实际视频的最后一帧，优先作为开场衔接参考，同时带入前视频的动作和运镜参考。即使下一镜已有手动首帧，同场景连续生成仍优先使用上一镜尾帧。从最终姿态和物件位置继续，不重复前一镜已经完成的动作，不重置场景。
   **重生成接回后镜**：单镜或局部批量重生成时，以后方紧邻且保留的视频实际首帧作为收尾目标；逐步达到对应姿态、道具状态、视线、运动方向、布局和光线，让后镜自然继续。仅使用同场景、同集的邻镜；缺少视频的一侧留空。本批选中的前镜等待新结果，选中的后镜不作为旧视频参考，避免新旧混用或循环等待。
3. **转场由剧本决定**：同场景使用一致的地点、内外景和时段标识。剧本明确改变地点或时段时按新场景生成，避免把旧场景尾帧强加给新场景；人物身份和音色设定继续保持一致。分集之间不自动衔接。
4. **人物不变形**：沿用选定人物参考图和角色设定，保持脸部身份、年龄、发型、服装和身体比例；禁止无剧情依据的换脸、变装、肢体增减、手部异常、形体扭曲或闪烁。
5. **环境和物品稳定**：保持场景几何、空间布局、光线方向、色彩以及道具形状、比例和状态；同场景镜头中禁止背景无故变化、物品凭空出现或消失。动作导致的位置变化必须连续且合理。
6. **音色稳定且正确对应人物**：固定每名说话人的身份标记、音色、年龄感、口音、音高范围和说话方式。前镜头有音轨时，使用 `video_audio` 参考已有音色和环境声；只有同一说话人才能复用对应声线，不把上一人物的声线套给下一人物。情绪可随剧情变化，声音身份保持不变。没有音轨时仅使用视觉参考，不伪造音频参考。
7. **对白准确、声音无异常**：逐字使用当前镜头剧本对白，保持原语言和说话顺序，不复制上一镜对白，不添加背景人声或乱说台词；语速自然、口型对应，禁止漏字、重复音节、截断台词、突然变声、爆音、蜂鸣、金属音或机械失真。无对白镜头不生成语音，未说话人物不做说话口型。
8. **失败和未知结果不得跳过连续依赖**：需要等待新结果的前镜失败、取消或缺少可用视频时，后续连续镜头暂停；固定的邻镜参考视频丢失时不提交。初始没有邻镜视频的一侧不建立依赖。提交结果未知时保留任务 ID，人工核实后恢复查询，不自动重新提交付费任务。修改前镜头后，已生成的后续视频标记为需更新。
9. **逐镜验收**：检查尾帧接续、人物与环境、对白、口型、音色和声音异常，再检查整集拼接效果。不合格镜头应修正设定或素材并由用户重新生成，随后更新受影响的后续镜头。上述质量要求是生成约束和验收标准；Ref2VA 的尾帧是参考条件，不能宣称精确锁帧、自动质检通过或零变形。

音轨参考接入依据：[RunningHub Ref2VA 节点实现](https://github.com/HM-RunningHub/ComfyUI_RH_MinMaxH3/blob/main/minimax_h3_nodes/api/conditioning.py)。声音参考与原对白区分依据：[MiniMax 官方全参考提示词指南](https://huggingface.co/MiniMaxAI/MiniMax-H3/blob/main/docs/VIDEO_PROMPT_WRITING_GUIDE_ref_en.md)。

### 台词与发音规范

1. **台词的唯一来源**是当前镜头的“对白 / 字幕”。拆分镜头时逐字连续分配剧本中的发言，保留原文重复，不加词、不少词、不改写、不同音替换。画面动作、资产设定、视频提示词和邻镜参考只说明视觉与连续性，不能增加可朗读的台词。台词只填实际要说的文字；动作说明另填，单人填说话角色，多人按发言顺序每行“角色：台词”，旁白填写“旁白”。
2. **提交前逐字核对**：镜头检查器的“实际朗读台词预览”和生成窗口的“台词与读音核对”使用同一份解析结果。RunningHub 提示词按目标片段发言顺序分配说话人 ID、语言及独立语音块，角色名称和说明不朗读。提交前检查所有语音块与当前台词的字词和顺序相同；语音控制标签混入对白或其他提示内容时阻止提交。此检查验证输入文本，不验证生成后的声音。
3. **读音独立指定**：检查器的“读音备注（不朗读）”每行填写 `词语=读音`，例如 `重庆=chóng qìng`、`ADHD=逐个读英文字母 A D H D`、`2026=二零二六`。词语必须出现在本镜台词中；备注仅指导该词发音，不额外说出、不替换对白正文。系统不猜测多音字读法。读音备注随任务的镜头快照固定，修改后已有视频标记需更新。
4. **给完整发言留足时间**：时长估算计入汉字、数字、英文单词及缩写逐字母读音，并保留基础开口和停顿余量。估算不是实际配音时长；过长台词必须拆镜，不能用抢读或截断来塞入镜头。提示词要求一句说完、句尾短暂留白，人声高于环境声，多人不抢话，禁止自行添加开场白、语气词、结尾或背景人声。原台词本来具有的语气词和重复照录。
5. **参考声音不带入旧词**：前镜音轨仅用于相同人物的音色和环境声参考，旧镜台词不能复制到当前镜头；不同人物不能套用同一声线。无台词的镜头不生成发言。
6. **成片逐字听检**：模型仍可能读错、漏字或加词。逐句核对实际音轨与朗读清单，确认人名、数字、术语、多音字、句首句尾及口型后再人工通过。现阶段没有自动语音识别验收，任务显示“完成”只表示素材生成和保存完成。上述规范不能保证声音百分之百逐字准确，也不会自动重提付费任务。需要更严格的字词控制时，应使用先审定配音、再由音频驱动口型的工作流；普通音轨参考不等于锁定输出语音。

### 剧本更新与视频存档

更新已有分集的剧本正文，会保存旧剧本、旧分镜和视频关联为独立存档，保留已有素材版本；当前导演台与成片页转到新剧本。随后用“AI 拆解分镜”创建新镜头。仅修改分集标题不会触发存档。

若该集还有未完成的视频任务，先完成或取消任务再改剧本。顶部“剧本与视频存档”可查看旧内容并播放旧视频；存档随项目 ZIP 导出，历史回滚不会删除已建立的剧本存档。

### 成片输出

- MP4：H.264 + AAC、30 fps，支持 1920×1080、1080×1920、1080×1080。
- 最终 MP4 和整集预览的右下角自动添加品牌名「幕织 Muweave」文字水印，保留安全边距；原始镜头素材不添加水印。Windows 使用系统微软雅黑字体。
- 按镜头顺序和设定时长拼接；画幅不符时等比例适配并补边，短视频补尾帧，长视频截断。
- 导入的配音优先，否则保留视频原音轨；没有音轨时补静音。
- 整集预览复用导出流程，更换视频、配音或时长后重新生成缓存。
- SRT 按镜头时长分配对白时间，不做语音强制对齐或字幕烧录；HTML 分镜表可打印。

## 插件与 Studio

插件复用桌面版的 SQLite 资料库、凭据、素材与任务队列。Studio 使用相同的剧本、资产、导演台、成片和任务界面，通过浏览器上传和下载文件。

### 构建插件

```sh
node scripts/prepare-ffmpeg.mjs
npm run package:plugin
```

产物位于 `release/`，版本号取自 [package.json](package.json)：

| 产物                                   | 用途                        |
| -------------------------------------- | --------------------------- |
| `muweave-plugin/`                      | Codex 本地插件目录          |
| `Muweave-<version>-plugin.zip`         | 插件归档                    |
| `Muweave-<version>.ipollowork-plugin`  | iPolloWork 手动导入包       |
| `.agents/plugins/marketplace.json`     | Codex 本地 marketplace 索引 |
| `iPolloWork-local-plugin-review.patch` | 本地插件审批入口的宿主补丁  |

构建不会自动安装插件，也不会把幕织内置到 iPolloWork。

### Codex

在幕织源码根目录执行：

```sh
codex plugin marketplace add ./release
codex plugin add muweave@muweave-local
```

重新加载插件或开启新对话后，可以要求“打开幕织 Studio”“写一集剧本并保存到幕织”“把这集拆成连续分镜”。支持 MCP Apps 的宿主可内嵌 `ui://muweave/studio`；其他界面打开 `muweave_studio_info` 返回的本机地址。

### iPolloWork

在“设置 → 扩展 → 插件 → 添加”中手动选择 `.ipollowork-plugin`。支持本地审批的宿主会展示权限、服务源码和文件指纹；审批后安装，再打开“幕织 Studio”。

仅接受签名本地服务的旧宿主会拒绝此开发插件。需要在兼容的 iPolloWork 源码中审阅并应用[本地插件审批补丁](scripts/ipollowork-local-plugin-review.patch)，或使用已提供该审批入口的版本。插件采用手动导入，不随 iPolloWork 内置或自动安装。

### 工具与运行环境

| MCP 工具              | 用途                                   |
| --------------------- | -------------------------------------- |
| `muweave_studio_info` | 获取 Studio 页面及本机连接地址         |
| `muweave_read`        | 读取项目、历史和任务                   |
| `muweave_edit`        | 编辑项目、分集、资产与分镜             |

iPolloWork 对应动作是 `studio-info`、`read`、`edit`、`generate`、`import`、`export`。视频提交和重试要求 `confirmed: true`，表示用户已授权该次付费生成；工具不提供密钥读取或替换能力。

本地插件需 Node.js 22.13+ 和幕织 0.2.x 运行环境，生成包默认指向当前已构建的源码。搬移源码或换电脑后重新构建并更新插件；可用 `MUWEAVE_HOME` 指向已构建目录，或 `MUWEAVE_EXECUTABLE` 指向相应版本的安装程序。

执行 `npm run build` 后，可用 `npm run studio` 单独启动后台 Studio。服务只监听 `127.0.0.1`，每次启动生成临时会话地址；不要公开或转发该地址。插件优先复用已有幕织进程；以 `--plugin-server` 启动的后台会在宿主关闭后继续处理任务，直到进程退出，不设置开机自启或 Windows 服务。

## 数据与备份

- **资料库**：实际路径可在设置页查看；Windows 默认在 `%APPDATA%/muweave/library/`。
- **数据库与文件**：`director.sqlite` 保存项目、对话、历史和任务；`projects/<id>/media/` 保存素材，`projects/<id>/chat/` 保存附件。
- **凭据**：RunningHub Key 由 Electron safeStorage 使用操作系统能力加密保存，不回传到前端，不进入项目 ZIP 或插件包。ChatGPT 文字和图片共用 Codex 账号授权。
- **访问方式**：桌面使用经过 Zod 校验的 IPC，Studio 使用带临时会话校验的本机 HTTP 服务，复用同一命令契约。
- **项目 ZIP**：包含当前项目、剧本存档、素材版本、对话附件和任务溯源记录；不包含 SQLite 历史回滚表、Key、账号会话或全局设置。导入恢复为新项目，旧任务不会自动执行。
- **容量与恢复**：ZIP 导出素材及附件总量上限 512 MB，导入检查安全路径和解压体积。最近 100 次项目内容修改可回滚，画布布局移动不创建历史版本。

大型项目可在停止桌面和 Studio 后备份完整资料库。删除项目或分集前，如需保留内容，请自行导出存档；删除操作不自动创建备份。

幕织没有项目云同步服务。主动调用 AI 时会发送相应提示词、附件内容或参考素材，因此本地存储不代表生成过程完全离线。

### 从旧 Director Desk 迁移

在旧版导出项目 ZIP，再在幕织“打开项目存档”中导入并重新连接账号。幕织使用独立应用标识和资料库，不自动复制旧 Key、浏览器会话或整个旧数据库。后续开发仅在本项目中进行。

## 常见问题与限制

| 情况                                 | 处理方式                                                                          |
| ------------------------------------ | --------------------------------------------------------------------------------- |
| ChatGPT 授权失效、生成超时或额度不足 | 查看实际错误，检查网络和账号；必要时在设置中重新连接，再人工重试                  |
| RunningHub 拒绝 Key 或节点           | 使用有 RH 币余额的消费级会员 Key；工作流变更后需要核对软件的节点契约，不绕过校验  |
| 创建任务超时，不知道是否已扣费       | 先核实平台任务和账单，绑定已存在的 Task ID；不要重复提交                          |
| 后续镜头暂停                         | 检查同场景前镜头是否完成、失败或取消，并处理前镜头任务                            |
| 成片没有整集预览                     | 确认当前集每个镜头都有可用视频，再检查 FFmpeg；Windows 发行包缺失二进制时重新安装 |
| 插件找不到 Studio 服务               | 检查源码是否已构建、插件路径是否有效；搬移目录后重新构建并安装插件                |
| 附件无法分析                         | 使用可提取文字的文件或支持的图片；扫描 PDF 不会自动 OCR                           |

视频结果下载限制为允许的 HTTPS RunningHub / xiaoyaoyou.com 子域，单文件最多 1 GB；其他 CDN、过期链接或不支持的格式需要人工下载导入，Task ID 会保留。

当前成片模块提供基础整集拼接，没有自动 TTS、口型同步、多轨剪辑、转场或自动配乐。人物、环境、首帧和对白的生成准确度需要人工审看。macOS 打包、账号生成及导出未进行实机验证。
